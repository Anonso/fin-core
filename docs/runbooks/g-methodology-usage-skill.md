# G 方法论使用指引（Codex skill 交付物，非运行时约束）

> 本文件是 G 方法论层（#13）的**应用层交付物**：人用指引，供 Agent 在拿到 G 方法论
> 投影（老师验证过的分析思路）时正确使用。**不进 FIN 代码、FIN 不读取、不进入
> Hermes/FIN 运行时、不约束 Agent 自然表达**；产品生效路径是 FIN code 的
> ContextPack 背景注入（background_guidance_only，不提升置信度）。
> 若未来 Hermes/Codex 开放 external skill seam，本文件可复制为对应 skill 目录，
> 但复制行为本身是独立立项，不改变本文件内容。

## 目的

G 方法论投影提供的是**老师原文确实出现过的分析框架**（如卡口分析、供需缺口、去日化
叙事），按 related_topics 确定性分组、逐条绑定 source_ref/generation。它不是结论、
不是当前观点、不参与置信度提升。**举一反三（跨板块泛化）是 Agent 自己的推理职责。**

## 拿到框架时的五个动作

1. **识别可迁移维度**：先判断该框架的核心变量是什么（卡口环节、供需缺口、叙事去日化
   的关键驱动），再判断这些变量在新板块/新标的上是否有对应物。没有对应物时，框架不适用，
   明说即可，不要硬套。
2. **列验证假设**：把"该框架在新场景成立"所需的假设显式列出（例如：卡口环节可识别、
   供需数据可观测、叙事仍在形成期），并给出可复核的时点与数据来源。
3. **不直接套结论**：框架是背景指引，不是答案。新板块的结论必须基于新板块自身的证据
   （行情、供需、公司事实、时点），不能用框架代替证据。
4. **标注原话与推演**：引用方法论时区分两层——
   - **老师原话**：framework/rule 本身（绑定 source_ref，Agent 可引用该来源）；
   - **你的推演**：你把框架迁移到新场景的判断（标注为推演，不得冒充老师观点）。
5. **允许失败**：方法论未命中、缺失、过期或截断时，按普通咨询回答即可；方法论投影
   缺失不构成任何回答义务，也不改变咨询契约。

## 边界

- 方法论投影 `usage_boundary=background_guidance_only_no_confidence_boost`：
  引用它**不提升**任何结论的置信度。
- 方法论规则有 365 天时钟：超过窗口的规则不会注入；Agent 不应主动引用已过期规则。
- 不把方法论注入当成 G 的"当前观点"：方法论与当前观点（mainline 投影）是两层，
  前者是分析思路背景，后者是当前视野。
- 单投研答案不变量：方法论只是输入之一，答案 owner 仍是分析 Agent。
