# 短设计：点线面分析顺序入人格（BUG-024 泛化 + 评分时间线升格）

> 状态：v1 待设计门。摸底依据：docs/pm/research/2026-09-03-point-line-plane-survey.md
> （owner 2026-09-03 立意 + 本报告结论 A+B2）。改后本文件随实现合入归档（规则 5）。

## 背景与问题

owner 立案 BUG-024：线类问题答案呈点状（缺最新信息层与情势结构）。v1 条款
（情势结构三层 + 最新信息纪律）只覆盖「标的/链条类」问题的输出形状。owner
澄清立意：点线面是**分析问题的逻辑思路**，应成为问询分析类问题的通用显式
顺序，尤其「先定面」——同一条线在磨市与单边趋势里含义相反，面的定性决定
线怎么读。摸底结论：点已过剩；线材料大多存在（评分时间线、mainline 演化、
日线序列）但未被点名使用；面来源单一（read_market_overview）且顺序未成文。

## 改动（consult-agent/CLAUDE.md，措辞级三处）

### 1. 新增一节「分析顺序（点线面）」，置于「判断循环（九步）」之后

```
## 分析顺序（点线面）

分析类问题（标的/行业/大盘/风格/事件/组合）按 面→线→点 组织思考，不是
点状堆叠后拼结论：
- 先定面：大盘环境定性（磨市/单边/极端避险……用主线环境刻度的系统层）与
  板块/风格结构位置——面决定下面每条线怎么读；
- 再连线：把关键变量画成时间线（评分温度变化、认知演化、行情节奏、消息
  序列），定位当前处于哪一阶段，给出现状→近期变化→下一步观察锚；
- 后落点：只取能校准线与面的证据点，带时点引用；不再改变线与面判定的点
  不堆（查询经济性照旧管停）。
线的标准来源：read_instrument_scores 评分时间线（最新=锚、旧行=演变）、
read_g_context mainline 认知演化、read_market_snapshot 行情日线、
read_market_overview 结构定性（定面）。来源缺哪层就如实说哪层缺，不拿
点冒充线、不拿线冒充面。
```

### 2. 「输出纪律」内 BUG-024 v1 情势结构泛化

- 适用范围：「标的、产业链条……类问题」→「一切分析类问题」；
- 结构前面加面层引导：答案开头一句定调 = 面层结论（环境/结构位置），
  随后按 线（短期/中期/长期锚）→ 点（关键证据与动作）呈现；
- 短期/中期/长期锚三行与最新信息纪律原文保留。

### 3. 九步循环零改动

九步编号不动（外部存在「九步循环第 N 步」引用）；分析顺序节与其互补，
不重排。步骤 5 的双查、步骤 8 的多因子合成原文保留。

## 不变量

- 证据纪律原样：只引用不编造、G 引用带时点、typed 缺口如实说；
- 九步编号与既有条款文字不动（除 §2 所指 v1 段泛化）；
- advisory-only 不变；查询经济性（停止查询纪律）继续管辖「点」的量。

## 验收

实弹两类问句各一：①「XX 行业现在到什么阶段」（线类）②「大盘结构怎么
样」（面类）——答案应现 面定调 → 线（阶段/时间线）→ 点（证据与动作）
结构，且引用带时点。owner 终验以日常实弹「线感/面感」为准。

## 固定四问（评审者逐条回答）

1. 契约破坏？新节与九步循环/查询经济性/主线环境刻度是否冲突或重复？
2. durable state 时序/幂等？纯人格措辞改动，是否有隐性 durable 依赖？
3. 引用闭包漏删？v1 情势结构泛化后，旧措辞是否有别处引用？
4. 相对直接 Agent 退化？强制结构是否催生模板化八股答案、稀释结论质量？
   这是最需要评审者把关的一条。
