# 使用回路配重方案 v1（usage-loop-rebalance）

> 状态：设计稿（待外审）。合入后本文件删除，Git 即归档。
> 规则 5 判据：C1 动问询动作合同（产品入口行为契约）+ C2 改板A 阶段门语义 → 按核心处理。
> 日期：2026-09-05 · 作者 CC · 立项：owner 船长复盘两轮讨论（09-04 夜 ~ 09-05）

## 1. 背景与问题（立项证据）

- **产能/使用失衡**：08-28~09-04 八天 344 提交（老仓 62 + 新仓 282）、立账 bug 32；
  记账真实使用（finq）仅 9 条（4y/5n，09-02 起记账）。D3 三天真实使用门挂在
  「建设完成后一次性执行」，无触发点，长期悬空。
- **owner 成本反驳（09-05，成立面吸收）**：使用数据当船长有试错/调试/时间成本——
  为试错而使用、在不理想产品上消耗真实工作流，都是对 owner 时间的征税；
  n=9 也支撑不了方向判断。
- **合成评审的循环盲区（实证）**：BUG-024 样本#1 在盲评 rubric、压测判分、
  人格验收探针全部 pass，只有 owner 带真实意图一问才暴露「形状达标、取材不达标」。
  合成法院的 rubric 由建造系统自己写，回路闭合，此类缺陷只在外部现形。
- **最高风险项**：BUG-031 两腿买点带零交集（中恒 34.5~35.5 vs 36.5~37.8），
  owner 实弹成交 15.561 落在两腿判定相反处；修复措辞级已施工，CC 腿无头探针
  PASS，codex 腿探针因 finqa-x 429 未发，恢复时点不可控。

## 2. 方案总纲

一句话：把「使用是唯一门」落成便宜机制——**pull-only 路由 + 事故仲裁记账 +
单腿披露（临时）+ D3 死触发 + meta 自审 + P5 冻结显性化**。零新设施、零 schema
改动；落点 = 文档四处 + 人格一行。

owner 成本反驳的吸收：使用不当船长（方向仍归 owner + 合成评审），只当**仲裁法院**
——只收 pull 案件、只强制事故记录。稀疏不碍事：本周 5 条 n 生成了几乎整周路线图
（BUG-024/029/030/031/002），4 条 y 的方向盘信息≈0——steering 靠事故，不靠体量。

### C1 腿间分歧披露（临时条款；唯一人格改动）

- 现状：BUG-031 两腿档位口径统一条款已施工未双验，codex 腿复验被 finqa-x 429 阻塞。
- 条款：复验闭环前，任一腿对「买卖档位/加减仓/动作预案」类问题给出**带具体价位**的
  建议时，答案末行固定标注（最终措辞施工时钉死）：
  「⚠ 单腿回答：两腿档位口径统一验证中（BUG-031），本答案未经另一腿复核。」
- 落点：consult-agent/AGENTS.md 动作合同段追加一行（symlink 双腿生效，备份 r13）。
- 退出条件：BUG-031 codex 腿探针 PASS 或实弹同题两腿一致 → 当日撤行（记账进 BUG-031）。
- 防滥用边界：只对动作类带价位建议触发；非动作题/无价位答案不标；不得泛化成
  一般免责声明。
- 为什么不是别的：干等 finqa-x 恢复（被动、无期）或维持现状（已知分歧带真金白银
  出门，owner 已被灼一次）均不可接受。

### C2 D3 重定义 + 死触发点

- D3 重定义：三个自然日 **pull-only 正常使用**——不要求增量使用、不要求覆盖面，
  只数事故（n、缺陷、摩擦）。
- 死触发点：决策日志 v1 施工收口当日，或 2026-09-07（周一）——**先到者开跑**。
  静默期约束：主线不开新设施（只修实弹暴露项）；决策日志施工豁免（已授权、进行中）。
- 预注册判据（防事后挪门）：
  - PASS = 三日均有 ≥1 条真实 pull 问询记账，且无「整链不可用」级事故存活过夜。
  - FAIL = 整链不可用当日未修，或 owner 出现「想问而因不信任没问」的弃用日
    （owner 主观报即可）。
  - PASS → 板A D3 销项，进 P4' 自然使用观察（无配额，rebaseline §0.5.1 原义）；
    FAIL → 事故按 BUGS 流程走，D3 顺延重跑，不开新设施、直接归因缺陷。
- 产出：D3 报告（事故清单/满足率/能力覆盖/owner 一句判语）入 $STATE 台账，
  NOW 板A 行销项或改判。

### C3 finq 记账口径：「n 强制、y 一字」

- y 记一字（保分母）；n 必须一句原因（not_best 字段）；存量 3 条 n 原因补注
  （owner 随手）。
- 性质改口：从「使用日志」改口「事故台账 + 稀疏满意度分母」。不加自动提醒、
  不改 schema（push 税禁止，不建新设施）。

### C4 能力使用路由（owner 行为侧约定）

- 优势面路由：G 覆盖/持仓/评分/时间线/黑话类走 FIN；其它题直连 Agent，
  不记账、不愧疚。
- 价目表纪律：运行态/问询验收中能力不接真实工作流（六档状态 = 使用定价）；
  现役运行态档 = update_user_watchlist，升档前不进 owner 日常。
- 落点：docs/pm/usage-profile.md 口述补录一节；NOW 板B 头部挂一行路由提示。
- 诚实分级：这是「约定」非「机制」，CC 无法强制；靠 finq 记录复盘可见即可，
  不为此建强制设施。

### C5 meta 设施家规10 自审 + P5 冻结显性化

- 决策日志、全部 skills（manage-zsxq-*、run-design-gate、book-shared-brain-learning
  等）、评审链适用家规10：至 2026-09-18 无真实使用记录 → 休眠候选清单。
  挂 NOW 待办一行（触发日 09-18）。
- P5/D-032 维持「只设计、不施工、D3 之后」——NOW 待办13 已是此状态，
  本条为显性确认，无文件改动。

## 7. 风险

- C1 被模型泛化成免责声明（每答必标）→ 触发面钉死「动作类 + 具体价位」；
  探针须验「非动作题不标」。
- D3 静默期误伤决策日志施工 → 豁免条款写死。
- C4 无强制力 → 接受为约定，复盘可见即可；不为此建强制设施。
- D3 判据含 owner 主观项 → owner 即 principal，主观判语是产品验收的合法证据
  （好用是唯一验收）。
