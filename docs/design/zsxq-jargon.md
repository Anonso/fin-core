# ZSXQ 黑话译注字典（短设计）

> 状态：设计定稿（v0.2，2026-09-03）。schema/词表档位已冻结；消费方契约见
> 「作用范围与消费方」。

## 背景与问题

G 原文在 ZSXQ 公开渠道常用隐语/谐音/隐喻（炒饭、柚子、凤仙郡、狮驼岭、科学家50 等）。
当前没有共享词表：学徒翻译是逐篇 LLM 解读，问询侧读到原文时可能解码失败（实例：
2026-09-03 问询把"科学家50"标为无法确认，实际 = 科创50）。需要一个单一、owner 可维护、
稳定的译注辅助层，不改写 G 原文。

## 范围与边界

- 只做「隐语 → 标准义」的译注数据，不改写任何原文/工件证据。
- 不做自动采词/自动学习、不做服务、不做复杂版本机制、不改 G 材料存储。
- 词目分三档：owner_confirmed（owner 口径）/ corpus_inferred（语料强佐证）/
  speculative（推测）。speculative 只进候选段，不进问询注入；corpus_inferred
  注入时标"语料推测"。
- 译注是**附加字段**：任何消费方拿不到该字段时必须保持旧行为不变（向后兼容，
  不因缺译注报错或降级），译注只增解释、不增职责。

## 数据形态

单一 JSON：`config/zsxq_jargon.json`。schema 草案：

```json
{
  "schema_version": "fin.zsxq-jargon/v1",
  "updated_at": "2026-09-03",
  "entries": [
    {
      "term": "科学家50",
      "meaning": "科创50",
      "kind": "指代",
      "confidence": "owner_confirmed",
      "evidence": ["zsxq-22258842281448251", "aaebffd7a76e"],
      "note": "owner 2026-09-03 确认；特刊标题平行结构佐证"
    }
  ]
}
```

字段：

| 字段 | 取值 |
| --- | --- |
| term | 黑话原词 |
| meaning | 标准义 |
| kind | 谐音 / 隐喻 / 指代 / 框架术语 / 栏目 |
| confidence | owner_confirmed / corpus_inferred / speculative |
| evidence | 文章 id 列表（可空，speculative 必填 note 说明来源） |
| note | 出处、时点、歧义说明 |

## 作用范围与消费方

译注只在三个落点存在，消费方各自按需读取，不建分发中枢：

1. **生成侧 prompt 注入**（已实现）：`thesis_extractor.py` 的 LLM 提取把
   「本文命中黑话对照」注入 prompt。作用域：deep-read 工件生成时让
   interpretation 尽量直接用标准义。LLM 抽样依赖，只作增强、不作必译验收。
2. **deep-read 工件结构化字段**（待实现）：生成 full/compact 工件时用规则扫
   原文命中词表，把命中项写进 payload 的 `jargon_notes`（确定性，同输入同输出）。
   这是跨消费方共享的唯一确定性译注源。
3. **读侧旁注**（待实现）：读原文类工具（`read_article`）返回时扫正文附译注行，
   覆盖不经 deep-read 工件的路径。

已知消费方与各自读到哪一层：

| 消费方 | 读到的黑话出现位置 | 覆盖层 |
| --- | --- | --- |
| deep-read 生成（ZsxqCognitionApprentice） | 原文 → evidence/thesis/interpretation | 1 |
| read_g_context 问询注入（runtime_context → 分层投影） | compact 的 guidance_brief/core_theses/methodology_rules | 2 |
| read_article 原文阅读 | 文章正文 | 3 |
| read_article_search 摘要/片段 | 命中文章的 excerpt | 3 + 查询双向扩展 |
| read_ready_evidence 参考材料 | reference_key_points/summary/selected_material | 3 |
| read_macro_brain 宏观 | 普通栏/每日热点摘要 | 3（低频） |
| Daily 生成器（daily_workspace_generator） | compact core_theses | 2 |
| cognition mainline 投影（readmodel） | information_units 派生的 themes/items | 2（间接） |
| 未来：Hermes 问询 agent（D-032 同源化） | 同一批 G 材料 | 2/3 复用 |

覆盖规则：凡消费 deep-read 工件者走第 2 层；凡直接读原文/摘要者走第 3 层；
两层的 loader 共用同一词表，不各自拷贝词义。

### 查询双向扩展（问询链必要项，2026-09-03 实测确认）

`read_article_search` 的 TF-IDF 召回与"黑话↔标准义"存在真实漏召回：实测检索
"科创50"命中不到 9/3 锐评（原文只写"科学家50"），检索"科学家50"才命中。
因此词表同时承担查询扩展职责：问句命中词表任一方向时，把反向词一并加入
检索词（"科创50"→附带"科学家50"；"科学家50"→附带"科创50"）。
只扩查询词，不改索引、不改原文。扩展只对 owner_confirmed/corpus_inferred
词条生效，speculative 不参与召回。

### 新增消费者的原则

会来新消费者（Hermes 同源化已在 NOW.md 排期），但**不为未知消费者预建管线**：
- 译注字段是窄契约：一个列表 `[{term, meaning, confidence}]`，附加在既有结构上。
- 新消费者接入 = 多读一个字段或调一次旁注函数，不改生成管线、不动词表。
- 旧消费者不读该字段也完全兼容；新增字段不 bump artifact_version/pipeline_version。
- 只有"消费者需要改写证据/生成新字段/要词表对撞语义"才重新开设计，其余一律
  按现有两层复用。

## 更新流与验证

- owner 给新词/修正 → 改 JSON（记日期 + 出处 + note）→ 跑 pytest →
  （仅 owner_confirmed）进入问询注入。不自动采词。
- pytest 校验：schema 合法、term 唯一、evidence 指向存在的文章文件；
  探针用 9/3 锐评 `zsxq-22258842281448251`，断言命中词均有译注且原文未被改写；
  工件层/读侧层各一条"有译注"与一条"无词表命中即不附加"的正反断言；
  查询扩展断言：检索"科创50"能命中 `zsxq-22258842281448251`。
- 本设计合入实现后删除（Git 即归档）。
